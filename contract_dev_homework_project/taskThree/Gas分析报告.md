## 项目概述
对比、分析三个版本智能合约的Gas消耗情况。

## 合约说明
### 原始版本（MathCalculator.sol）
+ 加、减、乘、除四个函数
+ 记录操作的事件
+ 独立的存储变量

### 优化版本1（OpMathCalV1.sol）
+ 优化内容：
    - 使用内联汇编进行溢出检查
    - 使用结构体存储操作数
    - 删除事件

### 优化版本2（OpMathCalV2.sol）
+ 优化内容：
    - 使用自定义 SafeMath 库保证不溢出
    - 多个变量打包单个存储槽
    - 使用位操作

## 总体性能分析
### 1.为什么优化版本1的Gas消耗量大于原始版本？
+ 态变量的存储布局（Storage Layout）差异：
    - 优化版本1中的 _calDate 是一个 struct，包含两个 uint128（各 16 字节），共 32 字节，要多占据一个存储槽，每次进行操作会增加**SSTORE 成本**。
+ 优化版本1的函数，每次调用都要进行两次SSTORE 操作（写 _result 和 _calDate）。

```markdown
  _result = a + b;
  _calDate = CalData(uint128(a), uint128(b));
```

+ 内联汇编可能比Solidity 0.8+ 默认启用的溢出检查，消耗更多Gas。

### 2.为什么优化版本2的Gas消耗量小？
+ 多个变量打包到了单个存储槽，大大减少函数调用时 SSTORE 的操作。
+ 位运算比结构体赋值更高效，位运算是纯计算操作，消耗Gas很少。
+ 函数中只给 result 一个变量赋值。

## Gas优化要点总结
+ 存储优化：
    - 打包变量到一个slot
    - 根据业务实际需求，优先使用小类型变量。一个slot最多存储32字节的数据，一个uint128占16位，两个刚好可以占满一个slot。注意：只有同类型变量才可以优化到一个slot中。
+ 计算与逻辑优化：
    - 使用 unchecked {} 避免不必要的溢出检查，更省Gas。
    - 用位运算替代乘除，左移 x << n 相当于 x * 2 的n次方，右移 x >> n 相当于 x / 2 的n次方。
    - 减少函数调用栈深度，a.mul(b).mul(c).mul(d) 可优化为 unchecked { a * b * c * d }。
+ 内存（Memory）与栈（Stack）优化：
    - 优先使用栈变量（stack）而非内存（memory），uint256 result = a + b; // 在栈上，免费。
    - 避免创建不必要的 memory 数组或结构体。
+ 函数与调用优化：
    - 使用 view / pure 函数可减少成本。
    - 减少 external 函数调用次数，多次调用同一函数可优化为调用一个批处理函数。
+ 避免昂贵操作：
    - 避免 require 字符串错误信息（除非必要），自定义错误消耗Gas少于字符串。
    - 避免 selfdestruct 和 new 合约。
+ 进行Gas消耗测试，每个测试准确记录Gas消耗量。
